# 原則

見た目の好みより、人が迷わず手元の作業を終えられるかを先に置く。

## 1. 目的が先、装飾は後

画面は「今なにをして、次に何が起きるか」が1呼吸で読める。ヒーロー文で世界観を説明しない。

## 2. 階層は型と余白で作る

色や影で階層をごまかさない。見出しサイズ、行間、ブロック間隔の3つで順位を付ける。

## 3. アクセントは決定に使う

森色（accent）は保存、次へ、成功。ナビ・カード枠・アイコン全部に塗らない。

## 4. 日本語を前提にする

本文は和文サンセリフ。行間 1.75、行長 35〜45 字。禁則を切らない。英語ラベルは短く併記してよい。

## 5. 状態を隠さない

disabled / loading / empty / error をデザインする。スケルトンだけで「動いている感」を出さない。

## 6. 動きは結果の合図

値が変わった、階層が変わった、成功した。それ以外は 180ms の色変化まで。

## 7. 検証はブラウザで行う

トークン一致だけでは足りない。実際の操作、フォーカス、縮小画面、Reduce Motion を見る。`DesignVerifier` と `DesignThinkingSkill` を使う。

## 根拠

HIG の明快さ、Material のトークン役割、taste-skill の反スロップ、Duolingo の「進行に色を使う」を最大公約数にした。
