# デザイン思考で UI を上げる

架空の「ユーザー」を置かない。対象が実在する作業者になるまで、画面を増やさない。

## 1. ペルソナ（最大3）

1人あたり次だけ。

- 名前（仮でよい）と役割
- 今の道具（競合、社内ツール、紙）
- 失敗したときのコスト
- 1回のセッションで終わらせたい作業
- 制約（片手、通勤、監査、日本語のみ、など）

デモグラフィックの埋め草（「30代、テック好き」）は捨てる。

## 2. ジャーニー

選んだ1人について、作業の前後を含めて6ステップ以内。

`きっかけ → 到着 → 理解 → 実行 → 確認 → 離脱`

各ステップに「見ているもの」「不安」「成功の合図」。不安がコピーや配置で消せるなら、コンポーネントを足す前にそれをやる。

## 3. ページフロー

画面を箱、操作を矢印。分岐は成功 / 失敗 / 中断の3本まで。

フローに現れない設定画面、モーダル、オンボーディングは削るか、フローに組み込む。

## 4. 実操作検証

`DesignVerifier` のキャプチャ表を、ペルソナの制約で上書きする。

例:

- 通勤片手 → 390px、親指到達、誤タップのundo
- 監査 → 破壊操作の確認文言がログに残る言葉か
- 日本語のみ → 英単語ラベルが意味を持つか（「Primary」は持たない）

キャプチャしながら「この人は今どこで止まったか」を書き、止まった箇所だけ直す。

## 5. 反映

直しの優先順位:

1. 目的が読めない（見出し、順序）
2. 次の手が無い（CTA、エラー）
3. 誤操作（ターゲット、確認）
4. トークンのずれ

見た目の洗練は4のあと。

## 禁止

- ペルソナを作って満足し、フローを描かないこと
- 全ユーザー向けの平均的画面を「誰にでも優しい」と呼ぶこと
- 検証なしのリデザイン一式

## 合格（これ以外は後回し）

- ペルソナは最大3。各人に作業 / 失敗コスト / 制約がある。デモグラは無い
- ジャーニーは6手以内。各手に見ているもの / 不安 / 成功の合図がある
- 分岐は成功 / 失敗 / 中断の3本まで
- キャプチャで止まった箇所だけ直した。一式リデザインしていない
