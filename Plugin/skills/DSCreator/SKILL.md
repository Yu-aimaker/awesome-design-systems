# 製品 DS を切る

AwesomeDS を土台にする。ゼロからトークンを発明しない。ブランドの決定が終わるまでファイルを書かない。

## 聞き方（grilling）

対象をデザインツリーにする。各決定は、それが確定しないと聞けない子を持つ。

**ラウンド**は、前提が揃った決定だけをまとめて聞く。依存する質問を同じラウンドに入れない。

各質問は次の形:

```
1. ❓ <短い題>
   <本文。事実は自分で調べ、決定だけ聞く>
   ➡️ 推奨: <1行>
```

ユーザーは番号で答えられるようにする。自分で決定を埋めない。コードベースや公開サイトで分かることは調べて、聞かない。

ラウンドのあとツリーを更新し、次のフロンティアを聞く。フロンティアが空になったら、共有できたか確認してから DS を書く。

## ツリーの幹（この順で親を潰す）

1. 誰が、何の作業を、どの頻度でするか
2. 信頼の置き方（冷静 / 学習ゲーム / 業務ツール）
3. 地の明るさ（白 / 墨）。中途半端な自動ダークは切る
4. アクセント1色の意味（進行、購入、危険回避、など）。汎用正本は青。Funnel は任意1–2
5. 書体: 和文必須か、見出しをセリフにするか
6. 密度（ダッシュボード vs 読み物）
7. 動きの強さ（taste-skill の MOTION 1–3 が既定）
8. 部品の借り先（Phase1 は shadcn 既定。Base UI 切替はしない）

子の例: アクセントが「購入」なら、成功色を同系にするか分けるか、は次ラウンド。

## 出力

確認後、製品リポジトリに次だけ置く。

- `DESIGN.md` — AwesomeDS からの差分（変えたトークンと理由）
- `tokens.json` — 数値
- 必要なら `CONTEXT.md` にブランド語彙を3–8語

変えていない規則は「AwesomeDS に同じ」と1行でよい。全文コピーしない。

## 禁止

- 質問を20個一度に出す（フロンティアを無視している）。
- 推奨なしの質問。
- ヒアリング中にコンポーネント実装を始める。
- ブランドが「特別だから」とトークン役割を壊す（danger を accent に再利用など）。

## 合格（これ以外は後回し）

- grilling が終わるまで DS ファイルを書いていない
- 出力は差分 `DESIGN.md` と `tokens.json` だけ
- 変えていない規則は「AwesomeDS に同じ」で、全文コピーしていない
- danger を accent / primary に再利用していない
- Funnel を CTA 全面に使っていない
